## False start (kept here as a warning)

First attempt produced a 10.8 MB rep showing only ~30 eager kernels. Looked broken. The sqlite revealed why:

```
kernels (CUPTI_ACTIVITY_KIND_KERNEL):   30
graph nodes (CUDA_GRAPH_NODE_EVENTS):   491,740   ← all duration 0, "Graph Node Creation"
```

**Cause**: sglang defaults to `enable_profile_cuda_graph=False` and `enable_layerwise_nvtx_marker=False`. With those off, `--cuda-graph-trace=node` only sees graph *metadata*, not per-node executions. The MoE-flashinfer path also disables piecewise cudagraph by default ("bypassed topk is incompatible with torch.compile"). Adding `--enable-profile-cuda-graph --enable-layerwise-nvtx-marker` to the server fixed it — kernel coverage jumped from a handful to the full set.

## Second issue: nsys version skew

The container's nsys is **2026.2.1.210**; my local nsys is **2025.1.3.140**. Reps are forward-incompatible, so `nsys stats` locally throws `Report was created in Nsight Systems version newer than your current version`. Workaround: added an `analyze_rep` modal function (CPU-only, no GPU) that re-runs `nsys stats --force-export` on the volume and writes CSVs back. Cheap (~2 min).
